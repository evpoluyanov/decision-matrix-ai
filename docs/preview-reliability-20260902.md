## 1. Архивная инструкция передачи пакета

Ниже сохранён первоначальный способ передачи изменений. Он уже выполнен в Codespaces; повторно применять patch не нужно. Текущий способ работы — публикация помощником в отдельную `codex/*`-ветку. Не выполняйте `git pull` поверх незакоммиченного ранее применённого пакета и не используйте reset для его удаления.

Скачайте `dmatrix-preview-20260902-v2.zip`, загрузите в Codespaces и распакуйте в отдельную пустую папку **вне репозитория**, например `/workspaces/dmatrix-preview-package-v2`. Внутри находятся полный `preview-changes.patch`, дополнительный `report-question-v1-to-v2.patch`, эта инструкция, отчёт аудита и черновик согласия. **Применять нужно только один из двух patch-файлов.**

Если предыдущий пакет `dmatrix-preview-20260902.zip` уже применён, оставайтесь в его рабочей ветке. Не переключайте её на main и не применяйте полный patch повторно. Сначала проверьте `git status --short`, затем:

```bash

git apply --check /workspaces/dmatrix-preview-package-v2/report-question-v1-to-v2.patch
git apply /workspaces/dmatrix-preview-package-v2/report-question-v1-to-v2.patch
git diff --check
DATABASE_URL=sqlite:// MIGRATION_DATABASE_URL=sqlite:// .venv/bin/python -m pytest -q
```

Ожидаются прежние незакоммиченные изменения пакета v1. Если есть свои дополнительные изменения или `--check` сообщает конфликт, остановитесь, не перезаписывайте их. При успехе переходите к разделу 2; шаги полного применения ниже пропустите.

**Если прежний пакет ещё не применяли**, используйте полный patch.

В терминале:

```bash
cd /workspaces/decision-matrix-ai
git status --short
git branch --show-current
git log -1 --oneline
```

Если есть свои незакоммиченные изменения — остановитесь и сохраните их отдельно, не делайте reset/checkout поверх них. Если дерево чистое, создайте отдельную локальную ветку от актуального `main` (если текущая ветка содержит неслитые изменения, сначала согласуйте основу):

```bash
git switch main
git switch -c codex/preview-reliability-favicon
git apply --check /workspaces/dmatrix-preview-package-v2/preview-changes.patch
```

При любой ошибке здесь остановитесь: не используйте принудительное применение, `--reject`, reset или автоматическое разрешение конфликтов. Если проверка успешна:

```bash

.venv/bin/python -m pip install -r requirements-dev.txt
git diff --check
DATABASE_URL=sqlite:// MIGRATION_DATABASE_URL=sqlite:// .venv/bin/python -m pytest -q
```

Переменные двух БД заданы явно только для тестов. Значения `.env` не изменяются. JS-тестам нужен Node.js. Если он отсутствует, pytest явно отметит пропуск — это не полная проверка JS.

## 2. Самый безопасный Preview — без платных запросов

Остановите прежний локальный сервер сочетанием Ctrl+C, чтобы освободить порт 8000. Запустите:

```bash
.venv/bin/python -m scripts.preview_mock_server
```

Этот **отдельный тестовый запуск**:

- создаёт новую SQLite-базу в системной временной папке, не открывая существующую;
- применяет миграции только к этой новой базе;
- создаёт искусственные аккаунты, проект и 100 оценок;
- возвращает искусственные ответы через MockTransport, без сетевого обращения к модели;
- не отправляет email, не подключает Метрику и не изменяет `.env`;
- сохраняет проверку входа, владения проектом и CSRF;
- сохраняет лимиты 3 операции/минуту, 30/сутки и дневной предел 100 ₽; все отображаемые расходы здесь **тестовые**, не списания MWS.

В панели **Ports** откройте порт 8000. **Visibility — Private**, не Public. Используйте выданный HTTPS-адрес Codespaces, не `dmatrix.tech`.

Учётные записи только этой тестовой базы:

| Назначение | Email | Пароль |
| --- | --- | --- |
| Обычный пользователь | `tester@example.com` | `preview-only-123` |
| Администратор | `admin@example.com` | `preview-only-123` |

Оба email подтверждены при создании **искусственных** данных. Это не изменение регистрации в Production. Войти обычным пользователем: `/login`, затем «Проекты» → «Демо 10 × 10» (`/projects/1`). Администратора удобно открыть в другом профиле браузера. После перезапуска демо создаётся новая база и новый ключ сессии; прошлые тестовые данные не загружаются. Не вводите реальные пользовательские данные в этот режим.

Самопроверка HTTP без запуска порта:

```bash
.venv/bin/python -m scripts.preview_mock_server --check --delay 0
```

## 3. Ручной сценарий — обычный пользователь

1. **Иконка:** откройте главную и четыре пути `/favicon.svg`, `/favicon-120.png`, `/favicon.ico`, `/apple-touch-icon.png`. В Network должны быть 200, SVG/PNG/ICO, без редиректа на вход. Проверьте вкладку на светлой и тёмной теме, мобильный экран и добавление на домашний экран. Браузер может кэшировать старую иконку — используйте новую приватную вкладку или отключённый кэш.
2. **Сохранение матрицы:** в «Демо 10 × 10» прокрутите к матрице, на узком экране сдвиньте её вправо, измените несколько оценок. Нажмите сохранение. Сразу видны спиннер и «Сохраняем матрицу…». Двойное нажатие не создаёт второй POST. После обновления остаётся рабочий блок, горизонтальная позиция и допустимый фокус. Откройте другую вкладку проекта и убедитесь, что значения сохранены. Обычное сохранение не добавляет ИИ-вызовов в админке.
3. **Конфликт:** откройте одну матрицу в двух вкладках до сохранения. Сохраните изменение в первой, затем другое — во второй. Вторая получает сообщение о смене версии (409), её ввод остаётся. Не должно быть тихого перезаписывания первой вкладки. Ссылка открывает актуальную матрицу отдельно для сверки.
4. **Ошибка связи при сохранении:** DevTools → Network → Offline, затем сохранение. Ввод остаётся. Верните Online и нажмите «Проверить сохранение». Если после сбоя изменили ввод, интерфейс предлагает сверку, не отправляя изменённые данные под старым ключом.
5. **Объяснение:** нажмите ИИ у объяснения результата. Окно ожидания появляется сразу. Закройте его (кнопкой, затем отдельным прогоном Escape), откройте «Показать состояние». В Network остаётся один POST. Результат появляется в существующем разделе, страница не возвращается в начало. Проверьте Tab/Shift+Tab, фокус после закрытия и узкий экран.
6. **Риски:** первый запуск в демо успешен. Второй намеренно получает некорректный JSON и показывает понятную ошибку. Старое объяснение, рейтинг и первый анализ рисков должны остаться доступны; кнопка выходит из состояния ожидания. Третий самостоятельный запуск снова успешен. При 429 подождите окончания минутного ограничения — его не отключали.
7. **Неизвестный исход/обрезание:** для отдельного чистого прогона остановите демо и запустите `--risk-mode timeout` либо `--risk-mode truncated`. Timeout — имитация, не ожидание реального провайдера. Неизвестный исход сохраняет резерв и предлагает проверять состояние, не повторяя платный запрос автоматически. Обрезание с известным usage сохраняет расчётную стоимость даже при failed.
8. **ИИ-матрица:** нажмите ИИ-заполнение. Уже существующий пакетный механизм показывает реальное число обработанных ячеек. Спиннер действует до окончания. Скрытие модального окна не означает отмену. Повторное нажатие не должно запускать вторую генерацию. После окончания проверьте 100 предложений и подтверждённые вручную значения.
9. **Два набора по пять:** создайте отдельный пустой проект с описанием. Дважды с принятием добавьте по 5 альтернатив, затем дважды по 5 критериев. Демо предлагает вес 10% — в сумме 100%. Убедитесь, что второй приём не удаляет первый. Учитывайте действующий лимит запросов в минуту.
10. **Отчёт:** кнопка находится после «Риски выбранной альтернативы». Открывается и без успешного анализа рисков. После первого успешного ИИ-действия в демо откройте отчёт: появляется «Насколько Decision Matrix AI помог вам принять решение?». До ответа обновите страницу — вопрос остаётся. Откройте этот отчёт во второй вкладке. В первой отправьте оценку, оставив комментарий пустым: сохранение успешно, вопрос исчезает. Обновите отчёт, выйдите/войдите и откройте его снова — вопроса больше нет. Вернитесь во вторую вкладку и через «Назад»: уже отвеченный вопрос не должен восстанавливаться из кэша. Даже POST старой формы не создаёт второй отзыв. Ограничение относится к пользователю, а не к одному проекту. Обычная «Обратная связь» остаётся доступна; её отправка сама по себе не считается ответом на этот вопрос.
11. **Тарифы:** `/pricing`, последовательность 99 ₽ → Pro → бесплатно → бесплатно ещё раз. «Текущий выбор» в правом нижнем углу, с рамкой; кнопки не сдвигаются. На мобильном нет наложений. После бесплатного варианта отдельное сообщение о бета-тестировании, без обещания письма; смена выбора не блокирует работу.
12. **Обратная связь:** отправьте текст с `<b>проверка</b>`; в админке он должен быть текстом, а не HTML. Проверьте статус и комментарий. Право на бонус возникает после подтверждения email, результата ИИ-проекта и отзыва, без начисления кредитов.

## 4. Администратор

Войдите `admin@example.com`, откройте `/admin`. Обычный пользователь по этому пути получает 403.

- При конечном выборе tester «бесплатно»: 99 ₽ = 0, Pro = 0, бесплатно = 1. Повторный выбор бесплатно не увеличивает показатели.
- Переключите 1/7/30 дней/всё время; прочитайте подпись выборки: текущий выбор уникальных пользователей с зарегистрированным просмотром предложения в периоде, не сумма нажатий.
- Тестовый администратор не участвует в воронке, но его расходы при запуске ИИ в своём проекте входят в техническую статистику.
- Разверните «Детализация последних 30 обращений»: отдельно видны расчёт API, защитная сумма, ID запроса/вызова и новые коды ошибок. Несколько строк с одним ID запроса означают несколько обращений внутри операции, например пакеты матрицы.
- Убедитесь, что бюджет 100 ₽ не изменён. Сумма бюджета может быть выше оценки API из-за округления токенов вверх до сотен по каждому обращению. Рассуждения повторно не прибавляются.
- Для ручной сверки внесите **тестовые** базовую стоимость, скидку, к оплате и оценку приложения; все суммы отображаются раздельно. Существующее поле отклонения означает «к оплате минус оценка», не расхождение базовых тарифов.
- Ответ на вопрос отчёта появляется один раз в обратной связи. Изменение его статуса на `resolved`/`rejected` не возвращает вопрос пользователю. Общие обращения этого же пользователя остаются отдельными записями.

## 5. UTM, аналитика, публичные страницы

UTM ручная проверка до этого была отложена. Откройте новое приватное окно **сразу** по `PREVIEW/?utm_source=telegram&utm_medium=post&utm_campaign=beta&utm_content=a`. Затем перейдите на такой же URL с `utm_source=vk`, зарегистрируйте отдельный тестовый аккаунт. В демо письма не отправляются. Первым источником в админке остаётся `telegram`; второй заход не меняет запись. Не путайте отсутствие email-письма в демо с ошибкой Production.

Для ручной проверки активации **нового UTM-аккаунта** нужен отдельный согласованный способ подтверждения тестового email или настоящая почта в обычном Preview. В этом пакете нет универсального обхода email-проверки. Автоматический тест связывания/активации уже входит в набор.

Метрика в изолированном демо намеренно отключена. Её ручной opt-in сценарий проверяется отдельно в согласованном окружении с тестовым счётчиком: до согласия нет загрузки/целей; отказ не ломает интерфейс; после согласия цели без user/project ID и текстов. На приватных страницах отключены автоматические просмотры/трекер ссылок; разрешённые продуктовые цели остаются.

Проверьте главную: CTA, примеры, метатеги и отдельную OG-картинку 1200×630. В демо `PUBLIC_SITE_URL` пустой: robots закрывает всё, sitemap пустой, публичная индексация намеренно не включается. Правила Production robots (главная, pricing, favicon, static) проверены автоматическими тестами; живой Production в этом пакете не менялся.

Юридические обозначения в регистрации и подвале остаются **неактивными**. Добавлено отдельное обозначение согласия; его черновик находится в `docs/legal/personal-data-consent-draft.md`. Не считать это утверждёнными документами или действующим механизмом получения согласия. Публикация — только после заполнения и отдельного согласования.
