# Детализация воронки — 08.10.2026

Владелец явно разрешил реализацию и немедленную публикацию в Production.

## Изменения

- Числа в колонках «Сессии» и «Не дошли с предыдущего» стали ссылками.
- `/admin/funnel/details` показывает составляющие число сессии, известный
  аккаунт/email, время по МСК, UTM и referrer. Гостя нельзя выдавать за человека.
- Используется общая выборка для суммы и списка: та же когорта начала сессий,
  фильтр источника, последовательность этапов и исключения.
- Администраторы/тестовые аккаунты исключаются по всем известным связям:
  аккаунт сессии, пользователь события, владелец или ожидающий сохранения
  аккаунт разбора. Вход связывает гостевую сессию даже без сохранения результата.
- Источник новой сессии — снимок существующей first-touch атрибуции, только
  после согласия. Referrer без query/fragment. События не содержат email/тексты.
- Для старых записей известен только ранее сохранённый источник. Источник
  регистрации аккаунта, если используется, явно подписан как таковой.
  Неизвестные источники не объявляются прямыми заходами.
- Список защищён существующей административной авторизацией, no-store/noindex,
  HTML-экранированием; 50 строк на страницу. Содержимое разборов не загружается.
- Включён ранее подготовленный PR17: запросы гостевого ИИ укладываются в
  действующие 4000 токенов; порции 3×4, без отсечения общего числа элементов.
  Предохранитель 100 ₽ и учёт реальных расходов не меняются.

## Миграция

`e2d202610008`, после `e1d202610001`: одно nullable TEXT-поле
`decision_journeys.attribution_json`. Исторические записи не переписываются.
Существующий запуск Docker применяет миграции перед стартом приложения.

## Ручная приёмка

1. Администратор открывает `/admin`, выбирает период и источник.
2. Нажимает число в строке этапа: число записей совпадает с итогом страницы;
   известный аккаунт показан с email, гость — отдельной анонимной сессией.
3. Проверяет источник, кампанию, страницу перехода и подписи исторических данных.
4. Проверяет «Не дошли с предыдущего» и возврат с сохранением фильтров.
5. Открывает нулевой счётчик: понятная пустая страница, без ошибки.
6. Проверяет, что собственные администраторские посещения не увеличивают цифры.
7. Неавторизованный посетитель попадает на вход; обычный аккаунт получает 403.

Списки отражают актуальные данные: между просмотром счётчика и переходом
новые действия посетителей могут изменить итог. Один человек с разными
сессиями не дедуплицируется в «уникального пользователя». Восстановить
личность гостя без известной связи с аккаунтом или отсутствовавший referrer нельзя.
